# 📚 Telegram-бот для обміну студентськими конспектами

Бот, у якому студенти діляться конспектами лекцій і знаходять конспекти своєї групи.
Інтерфейс українською. Самі файли зберігаються в Telegram (бот використовує `file_id`),
на сервері лежить лише невелика база даних SQLite.

## Можливості

**Для студентів**
- Вибір курсу (1–4) і групи; бачити можна лише конспекти **своєї** групи.
- Структура як у файловому менеджері: `1 курс › КН-11 › Предмет › Тема › Конспект`.
- Завантаження конспектів (PDF, DOC/DOCX, PPT/PPTX, XLS/XLSX, TXT, RTF, ODT, JPG, PNG),
  перевірка формату й розміру, захист від дублів. Однакові теми потрапляють в одну папку.
- Пошук за назвою конспекту або теми, сторінки, сортування за датою.
- **Тег автора:** автор для кожного конспекту сам вирішує, показувати свій @username чи ні;
  якщо показує, під файлом є кнопка «✉️ Написати автору».
- «🗂 Мої конспекти»: перегляд своїх, зміна тегу, видалення.
- «🚩 Поскаржитись» під чужим файлом.
- «💡 Пропозиції»: ідеї та повідомлення про проблеми для адміністратора.

**Для адміністратора** (`/admin`)
- Групи (з курсами), предмети, теми: додати, перейменувати, видалити (з підтвердженням).
- Конспекти: перегляд, фільтри, пошук, видалення. Користувачі: перегляд, блокування.
- Скарги й пропозиції зі статусами та сповіщеннями.
- Статистика (за 24 години, 7 і 30 днів), щоденні резервні копії бази в Telegram.

**Безпека:** токен і ID адміністраторів лише в `.env`; права адміна перевіряються при кожній дії;
захист від спаму; ліміти на розмір файлів, кількість завантажень, скарг і пропозицій;
користувач ніколи не бачить технічних помилок (вони пишуться в `logs/bot.log`).

## Структура проєкту

```
bot.py                  запуск бота
config.py               читання налаштувань (.env / змінні середовища)
database/               схема бази, оновлення структури (migrations.py)
services/               робота з базою, резервні копії, самопінг
handlers/               обробники кнопок і повідомлень (handlers/admin/ - адмін-панель)
keyboards/  states/     кнопки та кроки діалогів
middlewares/            права адміна, блокування, захист від спаму
utils/                  допоміжні функції
Dockerfile, docker-entrypoint.sh, litestream.yml   розгортання на Render
```

## 1. Запуск на своєму комп'ютері (Windows)

1. Встанови **Python 3.9 або новіший** (python.org), увімкни «Add Python to PATH».
2. Створи бота в Telegram: **@BotFather** → `/newbot` → скопіюй токен. Свій числовий ID дізнайся в **@userinfobot**.
3. Відкрий папку проєкту в VS Code → **Terminal → New Terminal** і виконай:
   ```
   python -m venv venv
   venv\Scripts\activate
   pip install -r requirements.txt
   ```
4. Створи файл `.env` (скопіюй `.env.example`) і впиши:
   ```
   BOT_TOKEN=123456:ВАШ_ТОКЕН
   ADMIN_IDS=ваш_telegram_id
   ```
5. Запусти: `python bot.py`. Зупинити: `Ctrl+C`.
6. У Telegram надішли боту `/start`; для адмін-панелі `/admin`.

> Файл `.env` містить секрети. **Ніколи не додавай його в GitHub** (він уже в `.gitignore`).

## 2. Налаштування (`.env` або змінні середовища)

| Змінна | Обов'язкова | Значення |
|---|---|---|
| `BOT_TOKEN` | так | токен від BotFather |
| `ADMIN_IDS` | так | ID адміністраторів через кому (максимум 5) |
| `DB_PATH` | ні | файл бази (за замовчуванням `data/bot.db`) |
| `MAX_FILE_MB` | ні | максимальний розмір файлу, МБ (20) |
| `UPLOAD_LIMIT_PER_HOUR` | ні | конспектів на годину від одного студента (20) |
| `BACKUP_ENABLED` / `BACKUP_HOUR` / `BACKUP_KEEP` | ні | щоденна копія в Telegram: увімкнено / година за UTC (3) / скільки копій зберігати (7) |
| `LITESTREAM_*`, `KEEPALIVE_URL`, `PORT` | лише на Render | див. розділ 5 |

## 3. Резервні копії та відновлення

- Щодня о 03:00 за UTC бот надсилає адміністраторам файл `.zip` з базою.
  Копію можна зробити й вручну: `/admin` → «⚙️ Налаштування» → «💾 Створити копію зараз».
- Перед кожним оновленням структури бази бот сам робить копію в `data/backups/pre_migration_*.db`.
- **Відновлення з копії:**
  1. Зупини бота.
  2. Розпакуй `.zip`, отримаєш `bot.db`.
  3. Заміни файл `data/bot.db` цим файлом.
  4. **Видали файли `data/bot.db-wal` і `data/bot.db-shm`**, якщо вони є (залишки старої бази заважатимуть).
  5. Запусти бота.
- У копії є дані користувачів (ID та імена): нікому її не пересилай.

## 4. Як розгорнути бота безкоштовно на Render

### Як це працює

Безкоштовний Render має два обмеження, які ми обходимо:

| Проблема на Render (Free) | Рішення в цьому проєкті |
|---|---|
| Локальний диск стирається при кожному перезапуску, засинанні й деплої | **Litestream** постійно копіює базу в **Cloudflare R2** і відновлює її при старті |
| Сервіс засинає після 15 хвилин без запитів | Бот відповідає на `/health` і **сам звертається до себе** кожні 8 хвилин |

Самі конспекти (файли) зберігаються в Telegram, тому на сервері лише маленька база.

### Крок 0. Що потрібно

- Акаунти на **GitHub**, **Render** і **Cloudflare**.
- Токен бота й твій Telegram ID (розділ 1).

### Крок 1. Код на GitHub

1. На github.com створи **новий приватний репозиторій** (наприклад, `konspekt-bot`), без README.
2. Перед завантаженням перевір, що файла `.env` немає в списку для додавання (він у `.gitignore`).
3. У папці проєкту (термінал):
   ```
   git init
   git add .
   git commit -m "Перша версія бота"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГІН/konspekt-bot.git
   git push -u origin main
   ```
   (Можна використати програму **GitHub Desktop**: Add local repository → Publish repository.)
4. Відкрий репозиторій на GitHub і переконайся, що там **немає** `.env`.

### Крок 2. Сховище для бази (Cloudflare R2)

1. У Cloudflare відкрий **R2 Object Storage** і активуй сервіс (Cloudflare може попросити додати платіжні дані, навіть для безкоштовного рівня: перевір це при реєстрації).
2. **Create bucket** → назва, наприклад, `konspekt-db`.
3. **Manage R2 API Tokens → Create API token**: дозвіл **Object Read & Write**, обмеж токен **лише цим бакетом**.
4. Збережи (показується один раз): **Access Key ID**, **Secret Access Key**.
5. Знайди адресу сервісу: `https://ВАШ_ACCOUNT_ID.r2.cloudflarestorage.com` (Account ID видно в налаштуваннях R2).

### Крок 3. Сервіс на Render

1. Render → **New → Web Service** → підключи свій репозиторій на GitHub.
2. **Language / Runtime: Docker**. Гілка: `main`. **Instance Type: Free**.
3. **Environment Variables** (змінні середовища):

   | Змінна | Значення |
   |---|---|
   | `BOT_TOKEN` | токен бота |
   | `ADMIN_IDS` | твій ID (кілька адмінів: через кому) |
   | `LITESTREAM_BUCKET` | `konspekt-db` |
   | `LITESTREAM_ENDPOINT` | `https://ВАШ_ACCOUNT_ID.r2.cloudflarestorage.com` |
   | `LITESTREAM_ACCESS_KEY_ID` | ключ з кроку 2 |
   | `LITESTREAM_SECRET_ACCESS_KEY` | секретний ключ з кроку 2 |

   Змінні `PORT` і `RENDER_EXTERNAL_URL` Render підставляє сам.
4. У налаштуваннях сервісу вкажи **Health Check Path:** `/health`.
5. Натисни **Create Web Service**. Перша збірка триває кілька хвилин.

> **Рекомендація для першого запуску:** спочатку розгорни **без** змінних `LITESTREAM_*` (лише токен і ID),
> переконайся, що бот відповідає, а потім додай змінні R2 (Environment → додати → збережеться й перезапуститься).
> Без `LITESTREAM_BUCKET` база **не зберігається** між перезапусками, тож це лише для перевірки.

### Крок 4. Чек-лист перевірки (дивись **Logs** на Render)

- Рядок `[entrypoint] Відновлюю базу з хмари...`, потім `[entrypoint] Запускаю бота з реплікацією бази`.
- Рядки від `litestream` про базу та реплікацію (точний текст залежить від версії).
- `База даних готова`, `Сторінка здоров'я запущена на порту …`, `Самопінг увімкнено: …`, `Бот запускається...`
- У бакеті R2 з'явилась папка `bot-db` з файлами.
- Бот відповідає на `/start`; у `/admin → ⚙️ Налаштування` написано, що реплікація **увімкнена**.
- Відкрий у браузері `https://ТВІЙ-СЕРВІС.onrender.com/health`: має бути `ok`.

### Крок 5. Обов'язково перевір відновлення бази

1. У боті додай тестову групу або предмет.
2. Render → твій сервіс → **Manual Deploy → Deploy latest commit** (або **Restart service**).
3. Дочекайся запуску й переконайся, що тестові дані **на місці**. Якщо так, збереження працює.
4. Видали тестові дані.

### Оновлення бота

Зміни файли, виконай `git add .`, `git commit -m "..."`, `git push`. Render оновить сервіс сам.
Структуру бази бот оновить автоматично (перед цим зробить копію).
**Оновлюй у час, коли студенти не користуються ботом:** під час деплою ненадовго можуть працювати
стара й нова версії одночасно, і зміни за цей час можуть не потрапити в збережену копію.

### Чесні обмеження безкоштовного Render

- Безкоштовних **750 годин на місяць** на акаунт; один сервіс без перерви використовує майже весь ліміт.
  Більше нічого безкоштовного в цьому акаунті на Render не запускай.
- Render може перезапустити безкоштовний сервіс будь-коли: бот на кілька хвилин замовкне, а потім
  сам відновить базу й продовжить. Дані не втрачаються, окрім змін останніх секунд перед збоєм.
- Якщо самопінг не допомагає і сервіс усе одно засинає (бот не відповідає через ~15 хвилин тиші),
  додай зовнішній безкоштовний пінгер (UptimeRobot, cron-job.org) на `https://ТВІЙ-СЕРВІС.onrender.com/health` кожні 5 хвилин.
- Як **друга страховка** працюють щоденні копії бази в Telegram (розділ 3).
- Для серйозного навантаження краще платний тариф із постійним диском (тоді Litestream не потрібен).

## 5. Типові проблеми

| Симптом | Що робити |
|---|---|
| `BOT_TOKEN не задано` | У `.env` (локально) або у змінних Render не заданий токен |
| Бот мовчить, у логах `Unauthorized` | Токен неправильний: скопіюй його з BotFather ще раз |
| Render: `[entrypoint] ПОМИЛКА: не задано змінну …` | Додай відсутню змінну `LITESTREAM_*` |
| Render: збій при відновленні, бот не стартує | Перевір ключі, адресу `ENDPOINT` і назву бакета. Бот навмисно не запускається, щоб не створити порожню базу поверх збереженої |
| `TelegramConflictError` у логах | Бот запущено в двох місцях одночасно (наприклад, на ПК і на Render). Зупини зайвий |
| Після змін немає кнопки в меню | Надішли боту `/start`, щоб оновилась нижня клавіатура |
| Адмін-панель не відкривається | Твій ID не в `ADMIN_IDS` |

## 6. Технічні відомості

Python 3.9+, aiogram 3, SQLite (aiosqlite, режим WAL), Litestream, Cloudflare R2.
Версія структури бази зберігається в самій базі; оновлення виконуються автоматично при запуску,
по одному кроку в транзакції, з попередньою резервною копією. Подробиці: `database/migrations.py`.
